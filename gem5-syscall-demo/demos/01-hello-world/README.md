# Demo 01: Hello World

## Overview

This demo showcases the most basic syscalls in gem5:
- `write()` - Output to stdout
- `exit()` - Terminate process

## What You'll Learn

- How gem5 intercepts syscall instructions
- File descriptor handling (stdout = fd 1)
- How data flows from simulated memory to host output
- Process termination in syscall emulation mode

## Files

- `hello.c` - Simple C program using write syscall
- `hello_raw.c` - Raw syscall version without libc
- `Makefile` - Build script
- `run_gem5.py` - gem5 configuration script
- `run.sh` - Convenience wrapper
- `README.md` - This file

```bash
# Build the demo
```

## The Programs

### hello.c - Using libc

```c
#include <stdio.h>

int main() {
    printf("Hello from gem5 syscall emulation!\n");
    return 0;
}
```

This uses standard libc `printf`, which internally calls `write()` syscall.

### hello_raw.c - Direct syscalls

```c
#include <unistd.h>

int main() {
    const char *msg = "Hello from raw syscalls!\n";
    write(1, msg, 26);  // Direct write syscall
    return 0;
}
```

This directly invokes the `write` syscall without buffering.

## Syscalls Used

### 1. write (syscall #1 on x86-64)

```
write(fd, buffer, count)
```

**Arguments:**
- `fd` (int): File descriptor (1 = stdout)
- `buffer` (void*): Pointer to data in simulated memory
- `count` (size_t): Number of bytes to write

**gem5 Flow:**
1. CPU traps on `syscall` instruction
2. gem5 extracts arguments from registers
3. Reads buffer from simulated memory using address translation
4. Calls host `write()` with buffer contents
5. Returns bytes written

**Why it's interesting:**
- Demonstrates memory→host data transfer
- Shows FD translation (target fd=1 → host stdout)

### 2. exit (syscall #60 on x86-64)

```
exit(status)
```

**Arguments:**
- `status` (int): Exit code

**gem5 Flow:**
1. gem5 intercepts exit syscall
2. Terminates simulated process
3. Reports exit status
4. Ends simulation

## Step-by-Step Execution

### 1. Program Compilation

```bash
gcc -static -o hello hello.c
```

The `-static` flag links libc statically, making the binary self-contained for gem5.

### 2. gem5 Loads Binary

```python
# In run_gem5.py
process = Process(cmd=['hello'])
system.workload = SEWorkload.init_compatible(hello)
```

gem5 loads the ELF binary:
- Parses ELF headers
- Allocates memory regions (text, data, bss, stack)
- Sets up initial register state
- Maps stdin/stdout/stderr (fds 0, 1, 2)

### 3. Execution Begins

CPU starts executing at entry point (`_start` in libc):

```asm
_start:
    ; Set up stack
    ; Call __libc_start_main
    ; Eventually calls main()
```

### 4. printf() Execution

When `printf()` runs:

```c
printf("Hello from gem5...\n");
  ↓
vfprintf(stdout, format, args);
  ↓
_IO_file_write(stdout, buffer, length);
  ↓
write(1, buffer, length);  // syscall!
```

### 5. write() Syscall

Assembly generated by compiler:

```asm
mov    rax, 1              ; syscall number (write)
mov    rdi, 1              ; fd = 1 (stdout)
mov    rsi, 0x401234       ; buffer address
mov    rdx, 37             ; count
syscall                     ; trap!
```

### 6. gem5 Handles Syscall

```cpp
// In gem5 internals

// 1. CPU detects syscall instruction
void ISA::handleSyscall(ThreadContext *tc) {
    int64_t callnum = tc->readIntReg(INTREG_RAX);  // rax = 1
    process->syscall(callnum, tc);
}

// 2. Look up handler
SyscallDesc *desc = getSyscallDesc(1);  // write

// 3. Extract arguments
int fd = tc->readIntReg(INTREG_RDI);          // rdi = 1
Addr buf_ptr = tc->readIntReg(INTREG_RSI);    // rsi = 0x401234
size_t count = tc->readIntReg(INTREG_RDX);    // rdx = 37

// 4. Read from simulated memory
char host_buf[37];
tc->getVirtProxy().readBlob(buf_ptr, host_buf, count);

// 5. Get target FD entry
FDEntry *fde = process->getFDEntry(fd);  // fd 1 → stdout

// 6. Write to host
ssize_t result = fde->write(host_buf, count);  // actual write()

// 7. Return result
tc->setIntReg(INTREG_RAX, result);  // rax = 37
```

### 7. Resume Execution

CPU continues after syscall:
- `printf()` returns
- `main()` returns 0
- `exit()` syscall called
- Simulation ends

## Experiments

Try these variations:

### 1. Multiple writes

```c
write(1, "Hello ", 6);
write(1, "World!\n", 7);
```

Observe two separate syscall entries in trace.

### 2. Error handling

```c
int ret = write(999, "test", 4);  // Invalid fd
if (ret < 0)
    perror("write failed");
```

See gem5 return `-EBADF`.

### 3. Large writes

```c
char big[100000];
memset(big, 'A', sizeof(big));
write(1, big, sizeof(big));
```

Observe memory copy overhead in statistics.

### 4. Write to stderr

```c
write(2, "Error message\n", 14);  // fd 2 = stderr
```

## Performance Analysis

### Syscall Overhead

Native `write()`: ~0.5 µs  
gem5 `write()`: ~500 µs (1000x slower)

**Breakdown:**
- Syscall dispatch: 20%
- Address translation: 30%
- Memory copy: 40%
- Host write: 10%

### Instruction Count

```
Total instructions: ~150,000
├─ libc initialization: 100,000
├─ printf formatting: 40,000
├─ write syscall: 5,000
└─ exit cleanup: 5,000
```

## Common Issues

### Issue 1: "Segmentation fault"

**Cause:** Stack not properly set up  
**Solution:** Ensure binary is statically linked or use gem5's FS mode

### Issue 2: No output visible

**Cause:** stdout buffering  
**Solution:** Use `fflush(stdout)` or write() directly

### Issue 3: Wrong output

**Cause:** Endianness mismatch  
**Solution:** Check target architecture matches binary
